Story: from C++ to the JVM

Why higher abstraction worked before: the tool kept a promise.

  1. Comparing observed bug and productivity rates for Java and C++
    Geoffrey Phipps. Software: Practice and Experience 29(4), 1999
    The real “Mark”: 2–3× more bugs per line in C++, up to 6× longer debugging, 30–200% more code per minute in Java.
  2. Hitchhiker’s Guide to Java Performance
    Ingo Düppe. JAVAPRO, 2025
    Early JVMs were 10–20× slower than C, then JIT and HotSpot closed the gap.
  3. A proactive approach to more secure code
    Microsoft Security Response Center, 2019
    About 70% of security fixes in C/C++ code are memory-safety issues, a class of bugs a managed runtime removes.
  4. Fortran
    IBM History
    The first big abstraction jump: around 1,000 hand-written instructions became 47 statements.
  5. The Mythical Man-Month
    Frederick P. Brooks. Addison-Wesley, 1975
    Productivity is roughly constant per statement, and coding is only about a sixth of the schedule.
  6. On the foolishness of “natural language programming”
    Edsger W. Dijkstra. EWD667
    Why natural language makes a poor contract with a machine.
  7. The Law of Leaky Abstractions
    Joel Spolsky, 2002
    Every abstraction leaks eventually. With an LLM, it leaks by design.

Bottleneck: the productivity paradox

Faster coding does not mean faster delivery. The slowest link sets the pace.

  1. State of AI-assisted Software Development
    DORA, Google, 2025
    AI is an amplifier: it magnifies the strengths of good organizations and the dysfunctions of struggling ones.
  2. The AI Productivity Paradox
    Faros AI, 2025
    Teams with high AI adoption merge far more PRs, but review time almost doubles and PRs get much larger.
  3. Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity
    Becker, Rush, Barnes, Rein. METR, 2025 (arXiv:2507.09089)
    Experienced developers were 19% slower with AI while believing they were faster. METR now treats this as a snapshot of early-2025 tools.
  4. Validity of the single processor approach to achieving large scale computing capabilities
    Gene Amdahl. AFIPS, 1967
    Amdahl’s law: speeding up one stage has a hard ceiling.
  5. Reevaluating Amdahl’s Law
    John L. Gustafson. Communications of the ACM 31(5), 1988
    Gustafson’s law: with more capacity, we take on bigger problems instead of finishing early.

Quality and security

More code is not the same as better code.

  1. AI Copilot Code Quality: 2025
    GitClear, 2025
    211 million changed lines: duplicated blocks up sharply, refactoring (moved code) down to under 10% of changes.
  2. GenAI Code Security Report
    Veracode, 2025
    Java had the highest security failure rate among tested languages. Models got better at syntax, not at security.

Requirements & design

Slow down to speed up: the spec is the contract the model doesn’t give you.

  1. Understanding Spec-Driven-Development: Kiro, spec-kit, and Tessl
    Birgitta Böckeler. martinfowler.com, 2025
    Three levels: spec-first, spec-anchored, spec-as-source. Also the warning: a spec bigger than the change is a disaster of its own.
  2. The New Code
    Sean Grove. AI Engineer World’s Fair, 2025
    The talk that put specifications at the center of AI-assisted engineering.

Implementation

Conventions, tests and loops: constraints the agent can check itself against.

  1. Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?
    Gloaguen, Mündler, Müller, Raychev, Vechev. ETH Zurich, 2026
    Human-written context files help a little, generated ones hurt, and all of them add cost. Write rules from real review comments.
  2. On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents
    Lulla, Mohsenimofidi, Galster, Zhang, Baltes, Treude, 2026
    With a human-written AGENTS.md, agents finished faster and used fewer tokens.
  3. Test-Driven Development for Code Generation
    Noble Saji Mathews, Meiyappan Nagappan. ASE 2024
    Giving the model tests up front solves more problems. Tests inferred from code can lock bugs in.
  4. TDD, AI agents and coding with Kent Beck
    The Pragmatic Engineer, 2025
    TDD as a superpower with agents, and agents that delete tests to make them pass.
  5. Mutation-Guided LLM-based Test Generation at Meta
    Meta, 2025
    LLM-generated mutants and tests on Android Kotlin code, many of which line coverage alone would have missed.
  6. Ralph Wiggum as a “software engineer”
    Geoffrey Huntley, 2025
    The Ralph loop: fresh context every iteration, one thing per loop, progress kept in files and git.
  7. Harness engineering: leveraging Codex in an agent-first world
    Ryan Lopopolo. OpenAI, 2026
    Around a million lines with no hand-written code. Progress stalled on missing environment capabilities, not on the model.

Limits

Tokens, sessions and budget are real constraints.

  1. Context Rot: How Increasing Input Tokens Impacts LLM Performance
    Chroma Research, 2025
    Across 18 models, performance becomes less reliable as input grows. A reason for small changes and fresh sessions.

Control & craft

Staying in control of the system, and staying sharp as an engineer.

  1. Ironies of Automation
    Lisanne Bainbridge. Automatica 19(6), 1983
    Automation leaves humans the hardest tasks while taking away the practice needed to do them.
  2. How AI assistance impacts the formation of coding skills
    Judy Hanwen Shen, Alex Tamkin. Anthropic, 2026 (arXiv:2601.20245)
    AI users scored 17% lower on understanding, most of all on debugging. Those who asked conceptual questions kept their mastery.
  3. The Impact of Generative AI on Critical Thinking
    Hao-Ping Lee et al. Microsoft Research and Carnegie Mellon, CHI 2025
    More confidence in AI goes with less critical thinking. More confidence in yourself goes with more.
